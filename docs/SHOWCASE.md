# What to showcase, and how

A menu of everything TazOS can demonstrate, split into operating-system
features and desktop features, followed by a running order for three minutes.

**A feature does not need a window to be worth showing.** The scheduler, the
MMU and ring 3 are the substance of an operating system and none of them have a
user interface. For those, the command output *is* the evidence and the source
is the explanation — open the file, point at the ten lines that do the work, and
move on. That reads as confidence, not as a gap.

---

## Operating-system features

Everything here runs from the shell, and each has code worth putting on screen.

| Feature | Show it with | Code to open | What it proves |
|---|---|---|---|
| **Preemptive scheduling** ★ | `spawn 3`, then `preempt off`, `spawn 3`, `preempt on` | [`kernel/context.asm:23`](../kernel/context.asm), [`kernel/task.c:321`](../kernel/task.c) | Tasks are interrupted by hardware, not cooperation |
| **Context switching** | same demo | `context.asm:23` — the register save, `esp` swap, and `ret` into another task | A task is fundamentally a stack |
| **Ring 3 privilege separation** ★ | `user`, then `user --syscall` | [`kernel/syscall.c:102`](../kernel/syscall.c) — the hand-built `iret` frame | The CPU enforces it, not a check in your code |
| **Virtual memory** | `mmu`, then `mmu 0` and `mmu 100000` | [`kernel/paging.c:37`](../kernel/paging.c) | Real page-table walks; page 0 unmapped on purpose |
| **Heap allocator** | `meminfo` | [`kernel/heap.c:49`](../kernel/heap.c) | First-fit with splitting, coalescing, corruption detection |
| **Race condition, then the fix** ★ | `race off` (wrong, and differently wrong each run), `race on` | `kernel/demos.c` | Genuine nondeterminism, not a staged bug |
| **Deadlock and recovery** ★ | `deadlock`, `deadlock kill`, `deadlock ordered` | [`kernel/demos.c:1010`](../kernel/demos.c) — the detector | Circular wait, detected, broken, then prevented by lock ordering |
| **Fault containment** | `fault div`, then `tasks` | `kernel/isr.c` | The offending task dies; the kernel does not |
| **Device drivers** | `lspci`, `date`, `disk`, `gpuinfo` | [`kernel/pci.c`](../kernel/pci.c), [`kernel/ata.c`](../kernel/ata.c) | Hardware discovered at runtime, not hardcoded |
| **Filesystem** | `write`, `ls`, `cat`, `rm` | [`kernel/fs.c`](../kernel/fs.c) | A namespace with allocation, release and metadata |
| **Persistence** | `disk` | `kernel/ata.c` | Real sector writes to an IDE drive |
| **Self-verification** | `selftest` | [`kernel/selftest.c`](../kernel/selftest.c) | 34 checks; each turns a mechanism off or reads a CPU-written value |

### The two strongest, and why

**The ablation.** `preempt off` is the single best thirty seconds available.
Anyone can print from three tasks; showing the interleaving *disappear* when the
timer stops driving the scheduler is the difference between a demo and a proof.

**Deadlock.** Two tasks take two mutexes in opposite orders and stop. The
detector notices the circular wait, `deadlock kill` breaks it by terminating a
victim, and `deadlock ordered` shows the same workload never deadlocking once a
lock order is imposed. Detection, recovery *and* prevention in one demo is more
than most course projects attempt.

### The line worth saying about the desktop

> "There is no graphics library underneath this. The kernel asks GRUB for a
> linear framebuffer, and every pixel, every glyph and the mouse pointer are
> written by code in this repository."

And on dragging, if anyone asks why it is smooth:

> "The window is rasterised once when the drag starts, and each frame moves
> those pixels and repaints only the strip it uncovered. That is what a
> compositor does. The first version repainted the whole desktop for every
> mouse packet and pinned the CPU at 100%."

## The three-minute running order

Six beats. Boot before recording — the self-test is 30–50 seconds of scrolling
and a third of the budget. Start on the prompt.

**0:00 — The verdict** *(10 s)*
Scroll to `34 passed, 0 failed` from boot.
> "Thirty-four checks. Each one either turns a mechanism off to prove it was
> load-bearing, or reads a value the CPU wrote."

**0:10 — Preemption, and proof** *(40 s)* ★
```
spawn 3
preempt off
spawn 3
preempt on
```
> "Three tasks, none of which yields. The timer takes the CPU from them. With
> preemption off they run one after another — the interleaving *was* the
> scheduler."

Cut to `context.asm:23` for five seconds.
> "That is the switch. Save the callee-saved registers, swap `esp`, and the
> `ret` at the end resumes a different task."

**0:50 — Ring 3** *(30 s)* ★
```
user
user --syscall
```
> "A task in ring 3 tried a privileged instruction. The processor refused, the
> kernel killed that task and carried on. Through `int 0x80` it succeeds —
> that is the one gate in the table with a privilege level of 3."

**1:20 — Deadlock** *(35 s)* ★
```
deadlock
deadlock kill
deadlock ordered
```
> "Two tasks, two mutexes, opposite orders. Both are blocked and neither can
> proceed. Detected, then broken by killing a victim — and with a lock order
> imposed, the same workload never deadlocks at all."

**1:55 — The desktop** *(55 s)*
```
gui
```
Drag a window. Open Notepad, type a line, save as `demo.txt`. Open File
Explorer — it is there, with its size and timestamp. Open Task Manager.
> "Same kernel; the shell is now in a window it is also drawing. The file
> manager holds no copy of the filesystem — it walks it every frame, which is
> why the file I just saved is already in the window."

**2:50 — Close** *(10 s)*
> "No operating system underneath any of it. It boots from GRUB, sets up its
> own descriptor tables, drives the hardware directly, manages its own memory,
> and draws its own desktop. About fifteen thousand lines."

## Leave out

- **`demo`** — the guided tour is far longer than three minutes.
- **`gputest`** — real, but explaining a command FIFO costs more than it returns.
- **3D acceleration** — the driver is complete and the adapter advertises the
  capability, but it reports a 3D hardware version of zero, so the pipeline is
  not available to this guest and the driver declines. Do not claim it. If
  asked, that the driver declines rather than issuing commands into a FIFO that
  will not execute them is a good answer.
- **Real hardware** — never attempted. Say so if asked.

## Questions to expect

- *Does it run on real hardware?* No. It is a GRUB rescue ISO and should boot on
  a BIOS or CSM machine, but that has never been tried.
- *Do files survive a reboot?* With an IDE disk attached, yes — `disk` shows the
  sector writes. Without one they live in the heap and do not.
- *Is memory protected between processes?* Instruction privilege is enforced by
  the CPU; the address space is not isolated. The whole first 4 MB is marked
  user-accessible. That is a documented scope decision, not an oversight.
